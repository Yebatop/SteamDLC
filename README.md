# SteamDLC

Все DLC ко всем играм твоей библиотеки Steam — одним списком, с фильтрами, скидками,
историей цен и уведомлениями.

Steam умеет показывать дополнения только по одной игре за раз. Когда в библиотеке
200+ игр, найти «что я ещё не купил к тому, во что реально играю, и что сейчас
со скидкой» практически невозможно. Этот сайт собирает всё в одну таблицу.

## Что умеет

- **Единый список DLC** по всем играм библиотеки: видно, что не куплено.
- **Цены и скидки** в валюте выбранного региона, сортировка по скидке, подсчёт
  суммы выбранного.
- **Приоритет по наигранным часам** — сортировка «сначала выгодное» поднимает
  дополнения к играм, в которые ты реально играешь, а не к тем, что лежат мёртвым грузом.
- **Фильтры**: поиск, только со скидкой, только из вишлиста, скидка от N%,
  цена до N, наиграно от N часов, жанры, типы (dlc / music / …), конкретная игра,
  скрыть недоступное в регионе и «скоро выйдет».
- **История цен** и отметка «минимум» — когда текущая цена не выше исторического минимума.
- **Уведомления в Telegram** о скидках на выбранные DLC.
- **Очередь покупок**: выбранные дополнения открываются по одному, купленное отмечается.
- Всё состояние (библиотека, фильтры, отметки) живёт в localStorage браузера.
  Аккаунтов и серверной базы с твоими данными нет.

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # вписать STEAM_API_KEY (или ввести ключ в интерфейсе)
npm run dev
```

Открыть http://localhost:3000 и пройти два шага онбординга.

### Деплой на Vercel

1. Импортировать репозиторий на [vercel.com/new](https://vercel.com/new) — Next.js
   определится сам, настройки сборки менять не нужно.
2. В Settings → Environment Variables добавить переменные из
   [`.env.example`](./.env.example). Минимум — ничего: ключ Web API можно ввести
   прямо в интерфейсе.
3. Deploy. Cron из [`vercel.json`](./vercel.json) будет ежедневно в 07:00 UTC
   снимать цены отслеживаемых DLC.

## Переменные окружения

| Переменная | Обязательна | Зачем |
| --- | --- | --- |
| `STEAM_API_KEY` | нет | Ключ [Steam Web API](https://steamcommunity.com/dev/apikey) для списка игр. Без него ключ вводится в интерфейсе и хранится в браузере. |
| `UPSTASH_REDIS_REST_URL` | нет | История цен и подписки. Без хранилища каталог работает полностью, но история не копится. |
| `UPSTASH_REDIS_REST_TOKEN` | нет | То же. |
| `CRON_SECRET` | нет | Защита `/api/cron/prices`. Vercel сам передаёт его в заголовке `Authorization`. |
| `TELEGRAM_BOT_TOKEN` | нет | Бот для уведомлений о скидках ([@BotFather](https://t.me/BotFather)). |

## Откуда берутся данные

| Что | Источник |
| --- | --- |
| Список игр и наигранные часы | `IPlayerService/GetOwnedGames`, официальный Web API. Профиль должен быть открыт: Настройки приватности → «Игровые данные» → «Для всех». |
| Список DLC у игры, цены, жанры | `store.steampowered.com/api/appdetails` — неофициальный эндпоинт витрины. |
| Какие DLC уже куплены | JSON со страницы `store.steampowered.com/dynamicstore/userdata/`, который ты копируешь сам из залогиненного браузера. |

Логин и пароль Steam нигде не нужны и не запрашиваются. `userdata` разбирается
прямо во вкладке браузера и на сервер не отправляется.

## Ограничения, о которых честно стоит знать

- **Добавить всё в корзину одной кнопкой нельзя.** Корзина Steam живёт в сессии
  магазина, и внешняя ссылка в неё ничего не кладёт. Поэтому сделана очередь
  покупок: страницы открываются по одной, на каждой — один клик «В корзину».
- **Купленные DLC без импорта `userdata` не определяются.** Web API отдаёт только
  игры. Импорт можно пропустить и отмечать купленное вручную.
- **Лимит запросов витрины** — примерно 200 запросов за 5 минут на IP. Синхронизация
  библиотеки на 200+ игр укладывается в лимит, но на общем IP Vercel можно поймать
  429. Синхронизация возобновляемая: прогресс сохраняется, кнопка «Продолжить»
  дозагружает остаток.
- **Регион.** Параметр `cc` меняет только валюту отображения. Купить по цене чужого
  региона нельзя — выбирай регион своего аккаунта.
- **Без Upstash** история цен не сохраняется между запросами, а подписки на
  уведомления недоступны.

## Если что-то не работает

На странице настройки есть кнопка **«Проверить доступ к Steam»** — она показывает,
что видит сервер: доступны ли оба сервиса Steam и принят ли ключ. То же самое
отдаёт `GET /api/diag` (доступность и какие переменные заданы) и
`POST /api/diag` с телом `{"apiKey":"..."}` (проверка конкретного ключа).

Частые случаи:

| Что видно | Что это значит |
| --- | --- |
| «Steam отклонил ключ Web API (403)» | Ключ скопирован не полностью, отозван или от другого аккаунта. Перепроверь на [steamcommunity.com/dev/apikey](https://steamcommunity.com/dev/apikey). |
| «Витрина Steam отклонила запрос с этого сервера (403)» | Steam не пускает IP дата-центра. Лечится запуском на своём компьютере вместо хостинга. |
| «Витрина Steam не приняла запрос (400)» | Ей незнаком набор запрошенных полей. Приложение перебирает наборы от лёгкого к надёжному, так что это сообщение означает, что не подошёл ни один. |
| «Steam не отдал N позиций» в шапке | Часть appid получить не удалось, остальные загружены. Нажми «Продолжить загрузку». |
| «Продолжу автоматически через N секунд» | Ограничение частоты у витрины. Ничего делать не нужно: загрузка сама возобновится, прогресс сохранён. |
| «Steam не вернул ни одного DLC» | Почти всегда ограничение частоты. Подожди несколько минут и продолжи; если повторяется — проверь кнопкой «Проверить доступ к Steam». |
| Загрузка DLC идёт долго | Это нормально: библиотека на 300 игр — это тысячи DLC и несколько минут запросов. Прогресс сохраняется, вкладку можно закрыть. |
| «Steam ограничил частоту запросов» (429) | Лимит витрины: ~200 запросов за 5 минут на IP. Подожди минуту и нажми «Продолжить» — загруженное не теряется. |
| «Steam не отдал список игр» | Закрытый профиль: Настройки приватности → «Игровые данные» → «Для всех». |
| «Не удалось соединиться» | Сеть не пускает к Steam: блокировка провайдера или сбой на стороне Steam. |

## Разработка

```bash
npm run dev        # дев-сервер
npm run build      # продакшен-сборка
npm run typecheck  # tsc --noEmit
npm test           # юнит-тесты (node --test)
```

### Структура

```
src/
  app/
    api/library/      список игр и наигранные часы
    api/dlc-ids/      пачка игр -> списки appid их DLC
    api/items/        пачка DLC -> цены, жанры, доступность
    api/history/      история цен из хранилища
    api/watch/        подписки на уведомления
    api/cron/prices/  ежедневный снимок цен + рассылка
    api/diag/         самодиагностика: доступность Steam и проверка ключа
  lib/
    steam/            клиент Steam: ретраи, батчинг, каскад filters, лимиты
    client/           состояние в браузере: синхронизация, фильтры, userdata
    kv.ts             Upstash Redis или in-memory заглушка
tests/                юнит-тесты фильтров, парсинга userdata, форматирования цен
```

Клиент Steam (`src/lib/steam/appdetails.ts`) устойчив к особенностям
неофициального API:

- **`filters` принимает только известные витрине имена.** На незнакомое она
  отвечает `400` с телом `null`, а не игнорирует его. Наборы перебираются
  каскадом (`src/lib/steam/filters.ts`), рабочий запоминается на время жизни
  инстанса.
- **Успех с пустыми данными — тоже отказ.** Группа `dlc` выглядит подходящей
  для списка дополнений и даже не вызывает ошибки, но витрина отдаёт по ней
  пустой объект: на библиотеке в 297 игр это дало ноль найденных DLC. Поэтому
  список берётся из `basic`, а пустой ответ считается поводом сменить набор.
- **Ограничение частоты не откатывает прогресс.** На `429` обход
  останавливается, уже полученное возвращается, а клиент ждёт (минута, две,
  пять) и продолжает с того же места. Внутри функции долгих пауз нет: у неё
  свой бюджет времени, а окно ограничения у витрины — минуты.
- **Батчинг `appids` нигде не обещан**: проверяем наличие каждого запрошенного
  appid в ответе и при обрезке переходим на одиночные запросы.
- **`success: false` — нормальный ответ** для снятого с продажи или
  недоступного в регионе DLC, а не ошибка.
- **Неудача на одной пачке не отменяет остальные.** Такие appid помечаются
  недоступными и считаются отдельно: лучше отдать 290 игр из 297, чем ничего.
  Исключение поднимается наверх, только если не получилось совсем ничего.
- **Размер пачки уменьшается вдвое, а не до единицы.** Пропуск пары appid —
  это делистнутые игры, а не сломанный батчинг; резкое падение до одного
  превращало один запрос в сорок и упиралось в таймаут функции.
- **У каждого запроса есть бюджет времени** (45 секунд при лимите Vercel в 60).
  По его истечении сервер возвращает обработанное вместе со списком
  `processed`, а клиент просит остаток следующим запросом. Поэтому большая
  библиотека не упирается в 504, а докачивается по частям.

Эти правила закреплены тестами в `tests/appdetails.test.ts` — они гоняют клиент
с подменённым `fetch`, без сети.
